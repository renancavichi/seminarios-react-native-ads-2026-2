Que problema o Expo UI resolve?

Visual “quase” nativo

View e Text são primitivas neutras. Seletores, menus e sheets que o usuário reconhece do sistema precisam vir de outro lugar, ou ser recriados.

Dependências demais

Picker, slider, pager, bottom sheet, menu: cada controle costuma ser um pacote nativo com release próprio, que pode quebrar a cada atualização de SDK.

Novidades do SO demoram

Um recurso novo, como o glassEffect() do SwiftUI, só chegava ao React Native depois que alguém escrevia o wrapper.

Solução: usar as primitivas que iOS e Android já entregam, como componentes React.

Como chegamos até aqui

Primeiro protótipo: alguns componentes soltos para SwiftUI e Jetpack Compose.

SDK 54

iOS: SwiftUI

Android: Compose

Switch vira o Material 3.

Não há reimplementação em JavaScript no meio: o componente que aparece é o do sistema. Dentro do Host, o layout é SwiftUI ou Compose, não flexbox do Yoga.

Host: a fronteira entre React Native e o nativo

Fora do Host

Valem View, Text, flexbox do Yoga, estilos e bibliotecas como NativeWind.

Dentro do Host

O layout é SwiftUI ou Compose: Row e Column no universal, HStack e VStack no SwiftUI.

RNHostView

Coloca views do React Native dentro de uma view do Expo UI, quando você precisa voltar ao mundo RN.

Como pensar

Trate o Host como uma ilha nativa na tela, por exemplo uma lista de ajustes, e mantenha o resto em View e Text.

Extensível: crie suas próprias views

  

    
O limite
SwiftUI e Compose têm centenas de views e modifiers. O Expo UI nunca vai embrulhar todos.

    
A saída
Você escreve suas views e modifiers nativos, e o Expo UI cuida do layout, das props e dos eventos.

    
O custo
É preciso conhecer um pouco de Swift ou Kotlin. Há guias de extensão na documentação para SwiftUI e Compose.

  







  
useNativeState: controles sem flicker

  

    
O que é
Um hook que cria estado observável compartilhado entre o JavaScript e as views nativas.

    
Para que serve
Controles dirigidos pela thread de UI, sem atraso entre o gesto e a tela.

    
Onde existe
Em @expo/ui/swift-ui e em @expo/ui/jetpack-compose.

    
Como pensar
Use o estado do React para a lógica da tela e o estado nativo para gestos contínuos, como arrastar um slider.

Tem alguma limitação?

  

    
Camada universal é a 1ª iteração
Alguns componentes funcionam bem nas três plataformas; outros não, porque SwiftUI, Compose e web não têm sempre a mesma primitiva.

    
Web ainda é experimental
Existem implementações web, mas sem o mesmo nível de qualidade do nativo.

    
Cobertura parcial
SwiftUI e Compose têm centenas de views. Só parte está embrulhada; o resto exige estender com Swift ou Kotlin.

    
Layout e estilo diferentes
Dentro do Host não vale flexbox do Yoga nem estilos no padrão CSS (como NativeWind). Visual segue cada sistema, não é pixel igual.

    
Drop-ins não são 100% idênticos
Muitas migrações são só trocar o import, mas algumas props mudam porque a base é SwiftUI e Compose, não UIKit e Android Views.

    
Algumas APIs não existem na TV
Em Apple TV e Android TV, certas APIs nativas simplesmente não estão disponíveis.

Misture ferramentas na mesma tela

  

    
View e Text
Design próprio, flexbox, NativeWind.

    
Expo UI
Ajustes, modais, pickers, sheets, tudo com cara de sistema.

    
react-native-skia
Gráficos, shaders e animações desenhadas.

    
WebGPU e TypeGPU
3D e computação na GPU.

    
DOM components
Código web numa webview, como shadcn.

    
Juntos
Combinam no nível do componente, na mesma árvore de views.

  







  
Quando usar

  

    
Escolha Expo UI quando
A tela deve parecer do sistema: ajustes, formulários, modais, sheets, menus, pickers.
Você quer reduzir pacotes nativos e ter uma só história de atualização.
Quer usar recursos novos do SwiftUI e do Compose assim que existirem.

    
Prefira outra ferramenta quando
O visual é totalmente seu: View e Text.
É gráfico, shader ou animação desenhada: Skia.
Já existe solução web pronta: DOM components.

  







  
Roteiro de código: App.js completo

  








  
Conclusão

  

    
Nativo de verdade
Expo UI traz SwiftUI no iOS e Jetpack Compose no Android para dentro do React, com um único import.

    
Pronto para produção
Estável desde o SDK 56 e já incluído no Expo Go, com drop-ins que reduzem pacotes nativos.

    
Use onde o sistema deve aparecer
Ajustes, formulários, pickers e sheets. Para o resto, View, Skia ou DOM components na mesma tela.

    
Com os pés no chão
Universal é a primeira iteração, web é experimental e a cobertura de componentes é parcial.
