                        Access token e refresh token

                        access token tende a ter vida menor. Refresh token permite obter novas credenciais e frequentemente tem vida maior; por isso, em uma arquitetura típica, merece maior atenção no armazenamento.

                        Os prazos e mecanismos de renovação dependem da arquitetura do backend. Refresh tokens podem expirar, ser revogados e sofrer rotação.

                          requireAuthentication pertence ao SecureStore

                          `SecureStore` guarda o segredo e pode exigir autenticação do dispositivo para acessá-lo. `LocalAuthentication` é outra biblioteca, usada quando queremos iniciar e controlar explicitamente o fluxo de autenticação local no aplicativo.

                          Trecho dentro de uma função async, com SecureStore importado. Use uma chave nova para o segredo protegido. No Android, a autenticação é exigida nas operações. No iOS, ocorre na leitura ou atualização, não na criação inicial. O exemplo não requer uma chamada prévia a authenticateAsync. Trate cancelamento, erro e retorno null. Para decidir se a proteção está disponível, consulte SecureStore.canUseBiometricAuthentication().

                            Limites da proteção biométrica

                            mesmo uma implementação biométrica correta não corrige vulnerabilidades em backend, gerenciamento de sessão, armazenamento incorreto ou comportamento do usuário.

                              Privacidade e LGPD

                              em autenticação local, o SO processa a biometria e o app recebe resultado. Em sistemas que capturam selfie ou outro dado biométrico, a aplicação pode efetivamente processar ou transmitir biometria. No Brasil, dado biométrico vinculado a uma pessoa natural recebe tratamento de dado pessoal sensível pela LGPD.

                              Uma selfie pode ser imagem pessoal sem necessariamente ser usada para identificação biométrica. A comparação trata de serviços que processam dados biométricos. O fato de o app receber somente o resultado local não elimina as demais obrigações de proteção de dados do produto.

                                  // 41/43 — iOS: Face ID/Touch ID protege a credencial no Keychain
import { useState } from 'react';
import { Alert, Button, Platform, View } from 'react-native';
import * as SecureStore from 'expo-secure-store';
const key = 'demo.ios';
const options = { requireAuthentication: true,
  authenticationPrompt: 'Acessar credencial',
  keychainAccessible: SecureStore.WHEN_UNLOCKED_THIS_DEVICE_ONLY,
};
export default function App() {
  const [ocupado, setOcupado] = useState(false);
  async function executar(preparar = false) {
    if (Platform.OS !== 'ios') return Alert.alert('Exemplo para iOS');
    if (!SecureStore.canUseBiometricAuthentication())
      return Alert.alert('Configure Face ID ou Touch ID');
    setOcupado(true);
    try {
      if (preparar) {
        // Na prática, use o token recebido após o login.
        await SecureStore.setItemAsync(key, 'TOKEN_FICTICIO', options);
        return Alert.alert('Demo pronta');
      }
      // No iOS, a leitura do item protegido abre o prompt do sistema.
      const token = await SecureStore.getItemAsync(key, options);
      if (!token) return Alert.alert('Credencial ausente: faça login');
      Alert.alert('Credencial acessada'); // Backend ainda valida a sessão.
    } catch { Alert.alert('Acesso cancelado ou credencial indisponível'); }
    finally { setOcupado(false); }
  }
  return <View style={{ flex: 1, justifyContent: 'center', padding: 24, gap: 16 }}>
    <Button title="Preparar demo" disabled={ocupado} onPress={() => executar(true)} />
    <Button title="Acessar credencial" disabled={ocupado} onPress={() => executar()} /></View>;
}

Instale expo-secure-store e configure o plugin expo-secure-store com faceIDPermission (NSFaceIDUsageDescription), depois gere um development build. Teste em um iPhone com Face ID ou Touch ID cadastrado. O botão Preparar demo salva somente um token fictício; no fluxo real, salve o token recebido após login. No iOS, criar o item protegido não costuma abrir o prompt; a chamada getItemAsync o solicita ao ler o item existente. requireAuthentication vincula a proteção à biometria atual e keychainAccessible limita o item ao aparelho desbloqueado, sem migração para outro dispositivo. Se a biometria cadastrada mudar, o item pode ser invalidado e a recuperação deve passar por novo login. A leitura local não valida a sessão no backend.

                                  // 42/43 — LocalAuthentication: o app pede biometria antes de ler
import { useState } from 'react';
import { Alert, Button, View } from 'react-native';
import * as LocalAuthentication from 'expo-local-authentication';
import * as SecureStore from 'expo-secure-store';
export default function App() {
  const [ocupado, setOcupado] = useState(false);
  async function executar(preparar = false) {
    setOcupado(true);
    try {
      if (preparar) {
        await SecureStore.setItemAsync('demo.prompt', 'TOKEN_FICTICIO');
        return Alert.alert('Demo pronta');
      }
      const hardware = await LocalAuthentication.hasHardwareAsync();
      const cadastro = await LocalAuthentication.isEnrolledAsync();
      if (!hardware || !cadastro) return Alert.alert('Biometria indisponível');
      const result = await LocalAuthentication.authenticateAsync({
        promptMessage: 'Acessar credencial', disableDeviceFallback: true,
        biometricsSecurityLevel: 'strong', // Esta opção vale para Android.
      });
      if (!result.success) return Alert.alert('Acesso não autorizado', result.error);
      const token = await SecureStore.getItemAsync('demo.prompt');
      Alert.alert(token ? 'Credencial acessada' : 'Prepare a demo primeiro');
      // O prompt controla este fluxo; o item foi salvo sem proteção biométrica.
    } catch { Alert.alert('Não foi possível acessar a credencial'); }
    finally { setOcupado(false); }
  }
  return <View style={{ flex: 1, justifyContent: 'center', padding: 24, gap: 16 }}>
    <Button title="Preparar demo" disabled={ocupado} onPress={() => executar(true)} />
    <Button title="Acessar credencial" disabled={ocupado} onPress={() => executar()} />
  </View>;
}

                                  // 43/43 — passkey: o dispositivo assina um desafio do backend
import { useState } from 'react';
import { Alert, Button, View } from 'react-native';
import * as Passkeys from 'react-native-passkeys';
export default function AcessarCredencial({ apiUrl, onSession }) {
  const [ocupado, setOcupado] = useState(false);
  async function acessar() {
    if (!Passkeys.isSupported()) return Alert.alert('Passkeys indisponíveis');
    setOcupado(true);
    try {
      // O servidor cria um desafio novo para este pedido de login.
      const inicio = await fetch(`${apiUrl}/passkeys/options`, { method: 'POST' });
      if (!inicio.ok) throw new Error('Desafio indisponível');
      const options = await inicio.json();
      // O sistema pode usar biometria ou PIN.
      const resposta = await Passkeys.get({ ...options, userVerification: 'required' });
      if (!resposta) return Alert.alert('Acesso cancelado');
      // O servidor verifica desafio, assinatura e origem da credencial.
      const fim = await fetch(`${apiUrl}/passkeys/verify`, {
        method: 'POST',
        headers: { 'Content-Type': 'application/json' },
        body: JSON.stringify(resposta),
      });
      if (!fim.ok) throw new Error('Assinatura recusada');
      const { accessToken } = await fim.json();
      if (!accessToken) throw new Error('Sessão ausente');
      onSession(accessToken); // A sessão vem do backend.
    } catch { Alert.alert('Não foi possível autenticar com passkey'); }
    finally { setOcupado(false); }
  }
  return <View style={{ padding: 24 }}><Button title="Acessar credencial"
    disabled={ocupado} onPress={acessar} /></View>;
}

                                  Demo 3: acesso com passkey
