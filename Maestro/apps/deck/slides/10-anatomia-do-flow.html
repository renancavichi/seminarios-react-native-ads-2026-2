Ato 03 · sintaxe

Anatomia de um flow

.maestro/flows/checkout.yaml
appId: com.exemplo.maestro
tags: [smoke, checkout]
env:
  PRODUTO: "Plano Anual"
---
- launchApp
- tapOn: "${PRODUTO}"
- assertVisible: "Resumo do pedido"
- tapOn:
    text: "Aplicar cupom"
    optional: true
- tapOn:
    id: "btn_pagar"
    label: "Confirmar o pagamento"
- assertVisible: "Compra aprovada"

appId — o endereço do app

É o package name no Android ou o bundle identifier no iOS. Sem ele o Maestro não sabe o que abrir. Em Expo Go se usa openLink no lugar.

tags — etiquetas de execução

Permitem rodar só um subconjunto: maestro test --include-tags smoke flows/. Clássico: no pull request roda só o smoke; de madrugada roda tudo.

env — variáveis

Interpoladas com ${VARIAVEL}. Podem vir do config.yaml, do próprio flow ou do terminal com -e SENHA=123 — é assim que segredo não vai para o Git.

--- — a linha divisória

Acima dela, configuração. Abaixo, a lista ordenada de comandos. É YAML puro: cada traço é um passo, executado de cima para baixo.

optional — o passo que pode faltar

Se o elemento não aparecer, o Maestro segue em frente em vez de reprovar o teste. Perfeito para banner de cookie, pop-up de avaliação e promoção que só aparece às vezes.

label — legibilidade do relatório

Troca o texto técnico por uma frase de negócio no log e no vídeo do teste. Quem lê o relatório vê "Confirmar o pagamento" em vez de "tapOn id=btn_pagar".
